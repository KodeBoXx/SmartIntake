01 — Foundation

Design Principles

Six commitments that guide every decision, from a button border radius to an enterprise workflow.

Trust First
Every interface element should communicate security, legality, and reliability. Certinal handles signatures on contracts — users need to feel safe, not confused.
Clarity Over Cleverness
Labels should say what they mean. Workflows should reveal their logic. When in doubt between interesting and clear, choose clear.
Speed at Scale
Enterprise users process hundreds of documents. Interactions must be fast — both technically and cognitively. Reduce steps, surface defaults intelligently.
Accessible by Default
WCAG 2.1 AA minimum for every component shipped. Accessibility is a first-class design constraint, not a post-launch audit.
System Coherence
A token changed once updates everywhere. Components inherit from the same primitives. No one-offs without a documented exception process.
Progressive Disclosure
Show only what the user needs at this moment. Advanced options reveal on demand. The signing flow should feel simple on day one and powerful on day 100.

Usage Rules

Do — Use Emerald 500/700 for primary interactive elements, CTAs, and focus states. Use Lime only as accent or for success/confirmed states. Use Cyan as info accent.
Don't — Mix Emerald and Lime in the same interactive element outside the gradient. Never use Lime 400+ on white backgrounds for body text (fails 4.5:1 contrast).

25 — Resources

Patterns

Reusable interaction patterns that combine multiple components into higher-level solutions.

Document Upload
Drag-and-drop target + file picker fallback + upload progress bar + validation feedback. Supports PDF, DOCX. Max 50MB. Viruses scanned on upload.
Signer Configuration
Add signer email → set role (signer, CC, approver) → set signing order → configure auth method. Each signer row uses Avatar + Input + Select + Toggle pattern.
Field Placement
Canvas-based drag-and-drop with Signature, Initial, Date, and Text field types. Color-coded per signer. Snap-to-grid at 8px.
Audit Trail
Chronological event timeline with icon + timestamp + actor + action + IP address. Filterable by event type. Exportable as PDF certificate.
Empty States
Branded illustration + headline + subtext + single primary CTA. Distinct states for: no documents, filtered empty, error loading, no results found.
Onboarding Flow
5-step wizard using Step Indicator. Skippable non-critical steps. Progress saved between sessions. Final step launches first document send.

Accessibility

WCAG 2.1 Level AA compliance is a baseline requirement. Every component ships with ARIA roles, keyboard navigation, and tested contrast ratios.

✓ All interactive elements reachable by keyboard (Tab / Shift+Tab)
✓ Focus visible at all times — 3px emerald-400 ring on all focusable elements
✓ All buttons and inputs have accessible names (aria-label or visible label)
✓ Status badges include text — color is never the only status indicator
✓ Modals trap focus and restore on close
✓ Live regions (aria-live) for Toast and async state changes
✓ Skip navigation link at top of every page
✓ Form errors linked to inputs via aria-describedby
✓ Minimum 44×44px touch targets
✓ Animations respect prefers-reduced-motion
⚠ Signature canvas requires keyboard-accessible alternative sign mode
⚠ PDF viewer requires accessible document view fallback
/* Focus ring — apply globally */ :focus-visible { outline: 3px solid var(--c-emerald-400); outline-offset: 2px; border-radius: var(--r-md); } /* Reduced motion */ @media (prefers-reduced-motion: reduce) { *, *::before, *::after { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; } }

How to consume this system in production — tokens, theming, component implementation, and contribution workflow.

Component Usage

// React component — Button import { Button } from '@certinal/ui'; function SigningAction() { return ( <Button variant="primary" size="lg" onClick={handleSign} aria-label="Sign Employment Contract" > Sign Document </Button> ); } // Prop types reference Button.propTypes = { variant: 'primary' | 'secondary' | 'ghost' | 'danger', size: 'sm' | 'md' | 'lg' | 'xl', loading: boolean, disabled: boolean, iconLeft: ReactNode, iconRight: ReactNode };

Contribution Rules

RuleDetail
Token-firstNever hardcode a hex, px value, or font string in component code. Always reference a token.
Light theme consistencyEvery new component must be reviewed for visual consistency in the light theme before PR merge.
Accessibility PR checkAll components need a keyboard walkthrough in the PR description.
Storybook storyEvery component needs Default, All Variants, Loading, Disabled, and Error stories.
No one-offsIf a design asks for something not in the system, file a token/component request first. No inline styles in product code.
ChangelogEvery change documented in CHANGELOG.md with semver bump. Breaking changes bump major version.
