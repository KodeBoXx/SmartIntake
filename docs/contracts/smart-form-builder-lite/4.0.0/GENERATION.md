# M2 contract publication generation

`capabilities.registry.json`, checked-in Java 17 models, TypeScript models, frontend AJV assets, and backend publication resources are generated by:

```bash
python3 tools/contracts/generate_contract_artifacts.py
```

The generator is pinned in its emitted `generation` metadata: generator version `1.2.0`, Python `3.12`, JSON Schema Draft `2020-12`, OpenAPI `3.1.0`, Java `17`, OpenAPI Generator `7.10.0`, openapi-typescript `7.6.1`, and TypeScript `5.8`. It deliberately writes no timestamp or absolute path. Java models are generated by the pinned `openapi-generator-maven-plugin` from a deterministic, local OpenAPI bundle that preserves the public OpenAPI/components and derives the seven schema roots, fields, and enums for offline generation. The drift gate regenerates the entire Java model set into a temporary directory and byte-compares it, removing stale model files during refresh. Canonical decimal and int64 values remain strings rather than floating-point numbers.

## Drift gates

The generator renders every output into a temporary directory before comparing bytes. The following commands fail when committed output drifts:

```bash
cd backend && mvn test
cd frontend && npm test
```

Both gates also run the schema and OpenAPI inventory validators. The server publishes the exact packaged schema and OpenAPI bytes, with SHA-256, `ETag`, `Digest`, and immutable cache headers. `/v1/capabilities` is deserialized directly from the registry; operation statuses are machine-readable. Only operations marked `implemented` claim behavior. All other inventory operations are explicitly `planned` contract publication, including the uncounted authorized-asset supplement.

`POST /v1/schemas/{kind}/{version}/validate` accepts at most 1,048,576 bytes and returns HTTP 413 above that bound. This protects the public publication validation route; evaluator semantics remain out of scope.
