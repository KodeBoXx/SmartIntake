# M2 contract publication generation

`capabilities.registry.json`, checked-in Java 17 models, TypeScript models, frontend AJV assets, and backend publication resources are generated by:

```bash
python3 tools/contracts/generate_contract_artifacts.py
```

The generator is pinned in its emitted `generation` metadata: generator version `1.3.1`, Python `3.12.3` (and enforces the Python `3.12` runtime family at startup), JSON Schema Draft `2020-12`, OpenAPI `3.1.0`, Java `17`, OpenAPI Generator `7.10.0`, openapi-typescript `7.6.1`, json-schema-to-typescript `15.0.4`, and TypeScript `5.8`. It deliberately writes no timestamp or absolute path. Java models are generated by the pinned `openapi-generator-maven-plugin` from a deterministic, local OpenAPI bundle that preserves the public OpenAPI/components and derives the seven schema roots, fields, and enums for offline generation. TypeScript transport projections are generated directly from all seven Draft 2020-12 schema sources. The drift gate regenerates the entire Java model set into a temporary directory and byte-compares it, removing stale model files during refresh. Canonical decimal and int64 values remain strings rather than floating-point numbers.

OpenAPI Generator has incomplete support for Draft 2020-12 root `oneOf` unions. The build-only OpenAPI projection supplies the discriminator-compatible common transport shape, so generated Java classes are DTO projections, not proof of semantic validity. Call `ContractRegistry.requireValid` before Java DTO deserialization; runtime NetworkNT and browser AJV both enforce the schema formats and bounds.

## Drift gates

The generator renders every output into a temporary directory before comparing bytes. The following commands fail when committed output drifts:

```bash
cd backend && mvn test
cd frontend && npm test
```

The backend gate deliberately runs `--scope backend` and never invokes frontend `node_modules`; the frontend gate runs `--scope frontend`. A full repository drift check uses the unscoped command. Both gates also run the schema and OpenAPI inventory validators. The server publishes exact packaged schema bytes with SHA-256, `ETag`, `Digest`, and immutable cache headers. `/v1/capabilities` is deserialized directly from the registry, retaining deprecated M1 `fieldTypes` and `operators` aliases derived from the richer catalog/signature data. Only the capabilities and schema publication routes are marked `implemented`; all other inventory operations are explicitly `planned` contract publication, including the uncounted authorized-asset supplement.

There is no public validator or OpenAPI endpoint. Validation is internal to the Java registry, and the checked-in OpenAPI remains a build and documentation artifact.
